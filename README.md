# Dibs

Headless slot-based booking engine for Laravel: **availabilities** generate **slots**,
**offers** hold them, **bookings** claim them; polymorphic **hosts** with roles. No UI,
no routes, no auth, no notifications — it fires events, consumers decide.

Everything *below* the waistline (slots, holds, claims, releases, assignment) lives
here and is identical in every project. Everything *above* it (who may publish, who
may see, what a meeting is for, how people are told) is yours.

The full design — lexicon, decisions, data model, behaviors, requirements ledger and
explicit non-goals — is `docs/SPEC.md`.

## Requirements

- PHP ^8.2, Laravel (`illuminate/*`) ^12 | ^13.
- **PostgreSQL 18+.** Primary keys are uuid v7 generated by the database
  (`uuidv7()` column defaults); the schema will not run on MySQL or SQLite.
- The application timezone stays `UTC` (Laravel's default). Dibs stores and compares
  UTC instants only; parsing and displaying wall-clock times is your job at the boundary.

## Installation

```bash
composer require robinsonryan/dibs
php artisan migrate
```

Publish only what you want to own:

```bash
php artisan vendor:publish --tag=dibs-config       # config/dibs.php
php artisan vendor:publish --tag=dibs-migrations   # once published, the package stops loading its own
```

## Configuration (`config/dibs.php`)

| Key | Default | Purpose |
|---|---|---|
| `table_prefix` | `dibs_` | Prefix for the seven tables the package owns. |
| `models` | package classes | Class-map: substitute a subclass of any package model; every relationship and query the package runs resolves through it. |
| `token_length` | `48` | Length of an offer's link token (never below 40). |

There is deliberately no timezone, permission or notification configuration.

## Concepts

| Concept | Model | States |
|---|---|---|
| A published window of bookable time | `Availability` | `draft` → `published` ⇄ `closed` |
| One bookable time | `Slot` | `open`, `held`, `booked` (= full), `retired` (history only) |
| The claim on a slot | `Booking` | `booked` → `completed` ⇄ `no_show`, or → `cancelled` (terminal) |
| A tokenized multi-slot invitation | `Offer` | `pending` → `accepted` / `expired` / `withdrawn` |
| Who fulfils a booking | any of your models, attached as a **host** with a `role` | pool on the availability, assignment on the booking |
| Who the booking is for / who submitted it | `bookedFor` / `bookedBy` (your models) | equal unless booked on someone's behalf |

**Tenancy.** An availability belongs to an optional *context* (your tenant / organisation
model). Every booking copies that context at creation — a direct booking takes it as an
option — and every offer takes one at creation, so `Availability::forContext($ward)`,
`Booking::forContext($ward)` and `Offer::forContext($ward)` answer "whose is this?" with
one indexed column and no join. Enforcing who may *see* what is still yours.

Buffers are availability parameters, not slot concepts: slot padding, minimum booking
notice, maximum booking horizon. Slots are bare start/end rows. A slot's **origin** is
derived: it either came from an availability or is *adhoc* (a direct booking or an
offer's own time).

## Usage

Every verb is an invokable action under `RobinsonRyan\Dibs\Actions`. Each runs in a
transaction and fires its event **after commit**.

### Publish time

```php
use RobinsonRyan\Dibs\Actions\{PublishAvailability, CloseAvailability, UpdateAvailabilityGeometry, DuplicateAvailability, DeleteAvailability};
use RobinsonRyan\Dibs\Data\AvailabilityGeometry;
use RobinsonRyan\Dibs\Models\Availability;

$availability = Availability::create([
    'context_type' => $ward->getMorphClass(), 'context_id' => $ward->getKey(), // optional owning scope
    'type' => 'temple-recommend',
    'name' => 'Sunday interviews',
    'starts_at' => $start, 'ends_at' => $start->addHours(2),   // UTC instants
    'slot_duration_minutes' => 15,
    'slot_padding_minutes' => 5,
    'min_notice_minutes' => 120,
    'max_horizon_days' => 30,
]);
$availability->hosts()->create(['host_type' => $bishop->getMorphClass(), 'host_id' => $bishop->getKey(), 'role' => 'interviewer']);

(new PublishAvailability)($availability);     // materialises the slot grid, fires AvailabilityPublished
(new CloseAvailability)($availability);       // open slots leave Slot::bookable(); rows and bookings untouched
(new PublishAvailability)($availability);     // reopen — generates nothing new

(new UpdateAvailabilityGeometry)($availability, new AvailabilityGeometry($start, $start->addHours(3), 20));
// regenerates OPEN slots only; held/booked slots survive untouched, even outside the new window;
// an open slot that carries a cancelled booking is retired (history kept, position reused)

$next = (new DuplicateAvailability)($availability, $start->addWeek(), $start->addWeek()->addHours(2)); // "every Tuesday" is a duplicate, not a rule
(new DeleteAvailability)($availability);      // throws DeletionRefused while any slot is held or has bookings
```

### Book

```php
use RobinsonRyan\Dibs\Actions\{BookSlot, CreateDirectBooking, CancelBooking, CompleteBooking, MarkNoShow};
use RobinsonRyan\Dibs\Data\{BookingOptions, AdhocSlotSpec, HostAssignment};
use RobinsonRyan\Dibs\Models\Slot;

$slots = Slot::bookable()->whereHas('availability', fn ($q) => $q->where('type', 'temple-recommend'))->get();

$booking = (new BookSlot)($slot, bookedFor: $member, bookedBy: $member);
// row-locked; validates open + published + future + notice/horizon + capacity;
// a pool of exactly one host per role is auto-assigned; fires BookingCreated

(new BookSlot)($slot, $member, $clerk, new BookingOptions(guardHostOverlap: true, type: 'calling-meeting'));
// guardHostOverlap throws HostOverlap if an assigned host already has an overlapping active booking

$booking = (new CreateDirectBooking)(
    $member, $clerk,
    new AdhocSlotSpec($start, $start->addMinutes(30), location: 'Bishop\'s office'),
    [new HostAssignment($bishop, 'interviewer')],
    new BookingOptions(context: $ward),       // an adhoc slot has no availability to inherit a context from
);                                            // adhoc slot + booking + assignment, one transaction

(new CancelBooking)($booking, cancelledBy: $clerk); // releases the slot: availability-born → open again; adhoc → kept as history
(new CompleteBooking)($booking);
(new MarkNoShow)($booking);                   // completed ⇄ no_show may be reclassified; cancelled is terminal
```

`OverlapCheck::for($host, $start, $end)` returns a host's overlapping active bookings
and is public regardless of the guard option. It is a query, not a solver: the package
never computes joint availability across resources.

### Offer

```php
use RobinsonRyan\Dibs\Actions\{CreateOffer, AcceptOffer, WithdrawOffer, ExpireOffers};
use RobinsonRyan\Dibs\Models\Offer;

$offer = (new CreateOffer)(
    offeredTo: $candidate,
    slots: [$slotA, $slotB, new AdhocSlotSpec($tuesday, $tuesday->addMinutes(30), 'Clerk\'s office')],
    expiresAt: now()->addDays(3)->toImmutable(),
    createdBy: $bishop,
    message: 'Pick whichever works.',
    context: $ward,
);                                            // holds the slots (they leave Slot::bookable()); fires OfferCreated

$offer = Offer::pending()->where('token', $token)->firstOrFail();   // the token is the only handle a link needs
$booking = (new AcceptOffer)($offer, $chosenSlot);                  // books it for the invitee even if the availability
                                                                     // has since closed; losers are released; fires OfferAccepted
(new WithdrawOffer)($offer);                                          // releases everything; fires OfferWithdrawn
```

Offers hold capacity-1 slots only. Who may *see* an offer is your concern (token
lookup + your authorization); the package guarantees only that held slots never
appear bookable.

Schedule the expiry sweep:

```php
// routes/console.php
Schedule::call(fn () => (new ExpireOffers)())->everyFiveMinutes()->withoutOverlapping();
```

It expires every pending offer past `expires_at`, releases their slots, fires one
`OfferExpired` per offer, and is idempotent. `AcceptOffer` also refuses an overdue
offer on its own, whether or not a sweep has run.

### Query scopes

`Availability::published()` · `Slot::bookable()` (open + published availability +
future + notice/horizon satisfied) · `Slot::upcoming()` · `Booking::active()` ·
`Booking::upcoming()` · `Offer::pending()` (pending **and** unexpired) · `Slot::retired()` ·
`forContext($model)` on `Availability`, `Booking`, `Offer`. Each time-based scope accepts an
optional reference instant.

### Events

`RobinsonRyan\Dibs\Events`: `AvailabilityPublished`, `AvailabilityClosed`,
`BookingCreated`, `BookingCancelled`, `BookingCompleted`, `BookingMarkedNoShow`,
`OfferCreated`, `OfferAccepted`, `OfferWithdrawn`, `OfferExpired`. Each carries the
affected model(s) with their relations loaded and fires after the transaction commits.
Hang notifications, reminders and workflow side effects on them.

### Exceptions

All extend `RobinsonRyan\Dibs\Exceptions\DibsException`: `InvalidTransition`,
`DeletionRefused`, `SlotUnavailable`, `HostOverlap`, `OfferNotAcceptable`,
`SlotNotOfferable`, `InvalidGeometry`.

### Extending the models

Models are not final. Subclass one, register it in `config/dibs.php` under `models`,
and the package uses your class everywhere — relationships, actions, factories.

## What it deliberately does not do

Recurrence rules, joint-availability solving, cross-availability conflict enforcement
beyond the opt-in overlap guard, notifications, UI/routes, authorization, timezone
display, payments, waitlists, partial holds on capacity-N slots, iCal export, bookings
spanning multiple slots. See `docs/SPEC.md` §9a.

## Development

```bash
ddev start
ddev composer quality     # lint:check -> analyze -> refactor:check -> test
ddev composer lint        # fix style
ddev composer refactor    # apply Rector
```

The gate is verify-only — it never rewrites your files. Tests run with Pest +
Orchestra Testbench against DDEV's real PostgreSQL (`testing` database; a checkout
nested at `.claude/worktrees/<slug>` gets its own `testing_wt_<slug>` automatically).
